---
name: qa-setup
description: One-time machine setup for qa-sdet - checks tools, offers the Pillow install, sets the Jira ticket prefix, and adds allow rules so auto mode stops blocking qa-sdet commands.
disable-model-invocation: true
---

`qa-mem` is the plugin's own command (its `bin/` folder is on the Bash PATH); only if the shell says `qa-mem: command not found`, use `python3 ${CLAUDE_SKILL_DIR}/../../bin/qa-mem` instead. Ask before every change; a step the user declines is skipped, not retried.

1. **Check:** run `qa-mem doctor` and show its output as-is.
2. **Pillow** (doctor line FIX for Pillow): explain it adds a text label (actual vs expected) beside the red box on evidence images; without it the box still comes from `playwright-cli highlight`, with no label. On yes, run the install command that FIX line gives (doctor picks `pip install --user` or, for an OS-managed python3, the OS package, which needs the user's own `sudo`: ask them to type `! <command>` themselves). Then run doctor again to confirm.
3. **Config:** if `~/.config/qa-sdet/config.json` is missing, follow the Config section of `${CLAUDE_SKILL_DIR}/../../references/run-setup.md` (it asks for everything, the ticket prefix included). If it exists without `jiraKeyPrefix`, ask for the project key typed before ticket numbers (e.g. `PROJ`) and add it. Also offer to set optional Jira workflow fields when missing: `jiraAcField` (custom Acceptance Criteria field, e.g. `customfield_10042`), `inboxJql` (custom JQL for `/qa-sdet:qa-inbox`, e.g. a QA queue), and `releaseTemplates` (release name patterns for pass-comment drafts). Every other `FIX` line step 1 printed about the config (a bad `qaBaseUrl`, `ssoHost`, `jiraKeyPrefix`, `jiraAcField`, `inboxJql`, …): handle it as that Config section says for doctor's FIX lines (the fix is the text after `->`; save the corrected value only on a yes; a declined fix stays open for step 6 instead of stopping setup), then run `qa-mem doctor` again.
4. **Auto mode:** run `qa-mem setup-permissions` and show the rules. Explain: these rules let qa-sdet's own commands (`qa-mem`, playwright-cli sessions `qa`/`qa-login`, read-only acli, the plugin's skills, reading the qa-sdet config file) run without a prompt and skip the auto-mode classifier; the plugin's guard hook still blocks unsafe calls (other hosts, Jira writes, cookie reads). They also cover the commands the explorer and mappers run; only starting an agent still goes past the classifier (auto mode drops `Agent` rules). The guard approves the calls it fully checked itself, and logs every denial (its own and the classifier's) to `<project>/qa-out/plugin-log.jsonl`. On yes: `qa-mem setup-permissions --apply` (it backs up `~/.claude/settings.json` first) and show what it added. Auto mode may refuse this, because it changes Claude Code's own settings: then ask the user to type `! qa-mem setup-permissions --apply` themselves (the `!` runs it as their own command). Tell the user to restart Claude Code.
5. **Old cookie file:** if doctor said `old cookie file`, offer to delete it (logins now live in the browser profile). On yes: `rm -f ~/.config/qa-sdet/qa-state.json`.
6. **Reply** in this order: one line per change made (or `nothing changed`), any FIX line from step 1 still open with its fix, then one next step: `/qa-sdet:qa-login` when doctor printed `FIX signed-in browser profile`, otherwise `/qa-sdet:qa-inbox` for your tickets.
