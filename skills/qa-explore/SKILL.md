---
name: qa-explore
description: Exploratory bug hunt on one or more pages of the QA web app (or changed/top pages from memory gaps), no ticket needed, with annotated bug images, repro specs and a readable report. Use when asked to explore or find bugs on a page, URL, changed pages or feature, or what to explore next.
argument-hint: <url | route | page name>... | --changed | --top N | --continue [run] | --discover [<url>] [--depth D] [--adaptive] [--faults] [--api-writes] [--focus '<charter>'] [--verify]
---

Explore and find bugs: $ARGUMENTS

Plugin root: `${CLAUDE_SKILL_DIR}/../..`. Project: `${CLAUDE_PROJECT_DIR}`. First read `${CLAUDE_SKILL_DIR}/../../references/run-setup.md`. `--faults` and `--api-writes` are optional and apply per page (they go to `qa-mem dispatch`); without them there is no fault injection and no write through `qa-mem api-probe` (reads always work). `--api-writes` lets the explorer send POST, PUT, PATCH and DELETE with `qa-mem api-probe`, only on `qa-sdet-` records it created: the mass-assignment probe. A run has no limit: each explorer goes until it reaches its verdict. `--focus '<charter>'` (optional, e.g. `--focus 'date filters across time zones'`) narrows the session to that charter: it goes to dispatch too, which puts it in the brief as `FOCUS: <charter>`.

1. **Config and target(s):**
   - No target and neither `--changed` nor `--top`: run `qa-mem gaps`, show its header and first 5 page lines, and ask which page(s) to explore (its `Next:` line is the top pick); go on with the answer.
   - `--changed`: run `qa-mem gaps --changed --top <N or 5> --json` (default cap 5 unless `--top N` is also given). If `pages` is empty, say no mapped pages changed since their last visit and stop.
   - `--top N` (without `--changed`): run `qa-mem gaps --top N --json`. If `pages` is empty, show `qa-mem gaps` and stop.
   - With `--changed` or `--top`, `pages` holds only routes an explorer can open: a detail route (`/incidents/:id`, also a deep one such as `/incidents/:id/history`) with an `entry_route` is dispatched as `--route '<entry_route>' --open-record --target-route '<route>'` (the explorer opens a record there and goes on to that page; its `entry_chain` lists the hops); `needs_id` lists detail routes nobody reached yet: don't explore them, name them in the reply.
   - Explicit target(s) (one or more URLs, routes or page names): a full URL as given (every URL's host must be in `allowedHosts`; if any is not, stop before opening the browser); a route is `qaBaseUrl + route`; a page name resolves via `qa-mem card '<name>'` (`qa-mem code` lists mapped pages; NO CARD: ask the user for the route and pass on the card's `tip:` line).
2. **Pre-flight session check** (run-setup): verify the QA session is active (recovering inline with headed `qa-login` if expired) before creating a run folder.
3. **Run folder and plan:** create ONE run folder: `qa-mem rundir '${CLAUDE_PROJECT_DIR}' --route '<route>'` for one page, `qa-mem rundir '${CLAUDE_PROJECT_DIR}' --label '<changed-Npages or explore-Npages>'` for 2+ pages. Write `<run>/.data/plan.json`: `{"kind": "explore", "title": "<route or comma-separated routes>", "created": "<date -u +%Y-%m-%dT%H:%M:%SZ>", "env": {"url": "<first target>", "browser": "<config browser>"}, "tickets": [], "cases": [], "questions": []}`; with `--focus` append `, focus: <charter>` to `title`. When the user listed checks to run, they are `cases` (fields in `${CLAUDE_SKILL_DIR}/../../references/planning.md`).
4. **Explore:** for each target page, sequentially (one explorer at a time; dispatch gives each route its own slug): `qa-mem dispatch '<run>' --route '<route>' --mode explore` (run-setup's Setup; plus `--focus '<charter>'`, the user's flags and, mid-batch, `--hypothesis`), delegate with its brief, teardown. After each teardown, `qa-mem next-action '<run>' <slug>` (run-setup's After each explorer): `continue` with the next page, `recover_sso` (sign in again, once per run, then that page again) or `abort` (skip the remaining pages, keep its reason).
With `--verify`: after the last teardown, run-setup's Second opinion (a `qa-sdet:qa-reviewer` read-only check of the serious drafts; its reply saved as `<run>/.data/review.json`).
**`--continue [run]`:** `qa-mem explore-next '${CLAUDE_PROJECT_DIR}' [--run '<run>']` prints `{run, incomplete_routes, leads, blast_radius_routes, frontier, run_patterns}` for the newest explore run (or the one named). Explore its `frontier` in order (unfinished routes first, then the pages calling a confirmed bug's endpoint, readers of what it saved, and the leads; at most 5 pages in all) as a new run (steps 2-5); when its `expand_recommended` is false (no HIGH lead, no confirmed bug that may reach other pages, no new 5xx: `expand_reason` says so) explore only the unfinished routes (`incomplete_routes`) and tell the user the rest would add little; `incomplete_routes`, `leads` and `blast_radius_routes` are the same pages unranked. Each item is dispatched with its `hypothesis`: `qa-mem dispatch '<run>' --route '<route>' --mode explore --hypothesis '<hypothesis>'`; a `:id` route has an `entry_route`: `--route '<entry_route>' --open-record --target-route '<route>'` instead, and one whose `entry_route` is null is named in the reply, not explored. Nothing left: say so and stop.
**Mid-batch (two or more pages):** after each teardown and `next-action`, while pages remain, run `qa-mem explore-next '${CLAUDE_PROJECT_DIR}' --run '<run>'`. When its `run_patterns` is not empty, pass the first entry's `hypothesis` as `--hypothesis` to the dispatch of every remaining page (the order of the user's pages never changes): a pattern a CONFIRMED bug showed on one page is tried first on the next.
**`--adaptive`** (only when given): after the last page's teardown, run `qa-mem explore-next '${CLAUDE_PROJECT_DIR}' --run '<run>'` and, only when its `expand_recommended` is true, explore up to 2 more pages from its `frontier` (best first; only routes on `qaBaseUrl`; a `:id` route only through its `entry_route`) in the same run, each dispatched as in `--continue` with its `hypothesis`, then report once: new pages never run ahead of the pages asked for. After the first extra page run `qa-mem explore-next` again and skip the second when `expand_recommended` is now false, or when that page's run file has no `bugs` and a `stop_reason` of `saturated` or `diminishing_returns`; say why you stopped. Without it, end the reply with those pages and `/qa-sdet:qa-explore --continue` as the next step when explore-next lists `incomplete_routes` or has `expand_recommended` true.
**`--discover [<url>] [--depth D]`** (read-only mapping instead of testing; no page needed): after steps 1-2, `qa-mem rundir '${CLAUDE_PROJECT_DIR}' --label discover; qa-mem marker start '${CLAUDE_PROJECT_DIR}'`, then `qa-mem discover '<run>' ['<url>'] [--depth D]` (the url's host in `allowedHosts`; default qaBaseUrl, depth 2, at most 25 pages) as one Bash call with `run_in_background: true`, and wait for its exit notice (no agent; it holds the `qa` browser meanwhile). It walks same-host links breadth-first (a query string is no new page, one sample per detail pattern, never logout, delete or sign-in links, never a click or typing), saves `<run>/.data/run-discover.json` after every page, and prints one JSON line (`status`, `pages`, `states`, `links`; BLOCKED exits 1 and its run file's summary names the fix). Then the teardown call; reply with the pages it found and their unvisited states (`qa-mem gaps`), and as next step `/qa-sdet:qa-explore --top 5`.
5. **Reply** (run-setup).
