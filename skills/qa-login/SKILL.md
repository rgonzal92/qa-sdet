---
name: qa-login
description: Sign in to the QA app once in qa-sdet's own browser profile (the user does SSO + MFA in a browser window); later runs reuse that login. Use when the user asks to log in or sign in to the QA app, or after qa-sdet said to run /qa-sdet:qa-login.
---

`qa-mem` is the plugin's own command (its `bin/` folder is on the Bash PATH); only if the shell says `qa-mem: command not found`, use `python3 ${CLAUDE_SKILL_DIR}/../../bin/qa-mem` instead.

0. If `playwright-cli --version` fails (not installed or broken), tell the user: "qa-login needs a working playwright-cli (`npm i -g @playwright/cli`). Without it, qa-explore and qa-ticket fall back to a Playwright MCP and ask you to sign in in that MCP's browser window when needed (it must run headed); the login lasts until Claude Code restarts." and stop.
1. Read `qaBaseUrl`, `ssoHost` and `browser` from `~/.config/qa-sdet/config.json` (if the file is missing, or `browser` is missing or not one of chrome, msedge, firefox, webkit, follow step C1 in `${CLAUDE_SKILL_DIR}/../../references/common.md`). Then `qa-mem doctor`: a `FIX` line about `qaBaseUrl` or `ssoHost` is handled as C1 says (step 5 compares the page's host with `ssoHost`, so a URL there would pass a failed sign-in).
2. `playwright-cli -s=qa close` (a run that was interrupted can leave its browser open on the same profile, and a profile opens in one browser only), then `qa-mem browser-open --session qa-login --headed '<qaBaseUrl>'`. It opens the persistent `main` profile. If it fails, show its first error line and stop, with the fix: for `Browser is already in use`, another qa-sdet browser still holds the profile (a run in another project folder, or an earlier qa-login window): close that window, or run `playwright-cli close-all` in that folder, then retry (never `--isolated`: that browser has no login); otherwise the fix `qa-mem doctor` prints (often `playwright-cli install-browser <browser>`).
3. Tell the user: "Complete SSO + MFA in the browser window, wait until the app's home page loads, then reply `done`." Then wait for `done`: the user enters credentials and MFA codes in the browser themselves; they never pass through you.
4. On `done`: `playwright-cli -s=qa-login close`. The browser writes the login into the profile itself.
5. Verify: `qa-mem browser-open '<qaBaseUrl>'` (headless), then `playwright-cli -s=qa --raw eval "location.host"`. Then `playwright-cli -s=qa close` (on both outcomes). Host is `ssoHost` or a login form showed → say the sign-in didn't stick and to run `/qa-sdet:qa-login` again. Otherwise run `qa-mem login-ok` (it records the sign-in, so `qa-mem doctor` stops asking for qa-login) and say: "Signed in. qa-sdet runs reuse this login until the app's SSO session expires; then run /qa-sdet:qa-login again. Next: /qa-sdet:qa-inbox for your tickets."
