---
name: qa-init
description: Warm up the QA memory from the app's source code. Maps routes, element locators, validation rules and API endpoints, and optionally confirms them in the QA app. Use when asked to init, map or pre-warm the project, or when cards say NO CARD for known pages.
argument-hint: [source folder…] [--full] [--crawl [--budget N] [--minutes M]]
---

Map the app from its source: $ARGUMENTS

Plugin root: `${CLAUDE_SKILL_DIR}/../..`. Project: `${CLAUDE_PROJECT_DIR}`. With `--crawl`, first read `${CLAUDE_SKILL_DIR}/../../references/run-setup.md`. Folder paths and other text go in shell commands inside single quotes, each `'` inside written `'\''`.

1. **Source folders:** the folders in the arguments, else `sourcePaths` from the config. If both are missing, ask the user once for the folder(s) of the app's code (frontend, backend, and e2e tests if they live elsewhere; absolute paths) and save them as `"sourcePaths"` in `~/.config/qa-sdet/config.json`.
2. **Scan (no model tokens):** `qa-mem codemap-scan --out '${CLAUDE_PROJECT_DIR}/qa-out/init' [--full] '<folder>' …` (single-quote each folder). It prints JSON: per area (frontend, backend, tests) the files, a token estimate and `mappers` (one entry per mapper: `scan_file`, `out`, `files`; a large area is split into several), and whether the scan is incremental (only files whose content changed since they were last mapped). Areas with nothing to read are already settled. If `skipped` lists a folder (not a folder, or too broad: the whole disk or home folder), tell the user and ask for the app's repo folder(s) instead. If the project is a git repo, make sure `qa-out/` is listed in the file `git -C '${CLAUDE_PROJECT_DIR}' rev-parse --git-path info/exclude` prints (append it when missing), so scans never get committed.
3. **Confirm when large:** if `total_files` > 150 or `tokens` > 300000, show the per-area counts, the number of mappers and the token estimate, and ask the user before going on (or offer fewer folders). Smaller scans (incremental re-runs usually are) go straight on.
4. **Map:** for each entry in every area's `mappers`, call the Agent tool with subagent type `qa-sdet:qa-mapper` (or `qa-mapper`), several per message so they work in parallel (at most 6 at a time). Each prompt contains, as literal text: `area=<area>`, `scan=<scan_file>`, `out=<out>`, `refs=${CLAUDE_SKILL_DIR}/../../references`; for frontend and tests also every frontend `scan_file` path (to Grep the router), and the routes `qa-mem code` prints when a map exists (they may be out of date when a router changed: the router wins). The plugin's hook ingests each file when its agent finishes. When all mappers are back, check every `mappers[].out`: it must have a `.ingested` file next to it. For an `.error` file, start that chunk's mapper again with the error text and tell it to Read its `out` and scan file, fix or remove the rows named, and Write `out` again. For an `out` with neither (the mapper never wrote it), start that mapper again as before. Files of a map that never lands are listed again by the next scan. An `.ingested` file may carry a `dropped rows:` line (rows with an unknown kind or no label) to mention in the report.
5. **`--crawl` (optional light verify pass):** config as run-setup says, then the setup call with `qa-mem rundir '${CLAUDE_PROJECT_DIR}' --label init-crawl; qa-mem marker start '${CLAUDE_PROJECT_DIR}' …` (no `card`), passing `--budget N` / `--minutes M` only when the user gave them (without them the crawl has no limit). Routes: every static one (no `:id`) from `qa-mem code`. Delegate with mode `map`, target `qaBaseUrl`, `out=<run>`, `slug=init-crawl`, faults no, the route list with, for each route, its `[locator]` lines from `qa-mem code '<route>'` verbatim, and these steps as literal text:
   > Do steps 1–3 once. Then for each route, in about 3 commands: (a) `goto <qaBaseUrl><route>` (one `/` between them); SSO or a login form: step 9 `BLOCKED` as in step 2. (b) One `--raw eval` that reports which locators exist: `getByTestId('x')` is `[data-testid="x"]` (also `data-test`, `data-cy`); `getByLabel('x')` is a label whose text is x, or `[aria-label="x"]`; CSS as written; for `getByRole('…', { name: 'x' })`, an element with that accessible name (button, link or input text). Also return `document.title` and any visible error text. (c) Record the route in `pages` with `locators` = only the confirmed ones, each `{"name": <its label>, "locator": <its value>}` copied character for character from the list (`[locator] Speed limit = getByLabel('Speed limit')` gives name `Speed limit`, locator `getByLabel('Speed limit')`; the memory matches the exact text). Leave the page's `name` out.
   > Submit nothing, type nothing. After the last route, step 9. The run JSON is `{"run_id": "map-init-crawl-<UTC yyyymmdd-hhmm>", "mode": "map", "target": "<qaBaseUrl>", "build": "<build>", "status": "COMPLETED | INCOMPLETE | BLOCKED", "summary": "…", "env": {"url": "<qaBaseUrl>", "browser": "<config browser>"}, "notes": "per route: loaded or not, locators confirmed out of checked", "pages": [{"route": "/x", "locators": [{"name": "…", "locator": "…"}]}]}`.

   Confirmed locators become verified for the current build. Afterwards the teardown call.
6. **Other folders in the map:** `qa-mem code --repos` lists every mapped source folder. If one isn't among this run's folders or `sourcePaths` (a moved or re-cloned repo, or one the user dropped), or it is flagged as no longer existing, ask the user whether to forget it, then `qa-mem codemap-forget '<folder>'`. Removing rows can't be undone, so never do it without a yes.
7. **Reply (≤10 lines), in this order:** pages, locators, rules and endpoints mapped (from `qa-mem code`); with `--crawl`, how many locators were confirmed and the `<run>/REPORT.md` path; what was skipped (chunks whose map never landed, `dropped rows:`, routes the crawl didn't reach); then one next step: a BLOCKED crawl's fix (e.g. `/qa-sdet:qa-login`), otherwise `/qa-sdet:qa-explore <page name>` (it now finds the page by name).

Re-run `/qa-sdet:qa-init` after code changes; cards say when the map is behind HEAD. Re-runs read only changed files (all of the frontend when a router changed): a new file-routed page that reuses unchanged components gets their locators with `--full`.
